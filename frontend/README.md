# frontend · 路书（智能出行助手前端）

React 19 + Vite 7 + TypeScript 前端，配 LangGraph 后端（`../api_server.py`）。交互地图用 Leaflet + OpenStreetMap 底图。

## 开发

```bash
cd frontend
pnpm install        # 或 npm install
pnpm dev            # http://localhost:5173，/api 代理到 http://127.0.0.1:8000
```

后端（仓库根目录）：

```bash
python api_server.py    # 未配置密钥也能启动；真实规划需要 DASHSCOPE_API_KEY
```

不配任何 Key 时后端是可用的降级模式：`GET /api/health` 探活和 `GET /api/trips/example` 内置示例正常返回；`POST /api/trips/plan`、`/chat` 返回明确的 503，不会伪造结果。真实生成行程需要 `DASHSCOPE_API_KEY`；真实坐标和导航路线另需 `AMAP_API_KEY`，不配时站点坐标为 `null`、路段为 `unavailable`，前端不画线。Key 的配置方式见根 README 的 `.env` 说明。

后端未就绪时可先用开发桩看界面。注意：**桩只提供固定示例和探活，不提供规划**。

```bash
# 终端 A（frontend/ 下）
pnpm stub              # 开发桩，监听 127.0.0.1:8001：GET /api/health、GET /api/trips/example
# 终端 B（frontend/ 下，Windows PowerShell）
$env:VITE_API_BASE="http://127.0.0.1:8001"; pnpm dev
# 或 bash: VITE_API_BASE=http://127.0.0.1:8001 pnpm dev
```

桩返回的是写死的杭州示例，标题、摘要和 warnings 都标了「固定示例」：所有路段只有「示意直线」或「路线不可用」，`distance_m` / `duration_minutes` 一律为 `null`，没有真实导航数据。`POST /api/trips/plan` 直接返回 503，`detail` 说明请启动配置密钥的后端，不会伪造 `source: "agent"` 的结果。需要真实规划时启动 `python api_server.py`。

## 本地保存

- 只有点「保存当前行程」才写入，页面加载、恢复、导出都不会顺手保存。
- 数据写入当前浏览器、当前网址（同源）的 localStorage（键 `travel-assistant:saved-trips:v1`），不上传、不跨设备同步。最多 20 份，单份约 640 KB，总计约 1.5 MiB（1 536 KB）；同一 `trip.id` 再次保存只更新原记录。
- 结构校验对齐后端契约（`travel_itinerary.py` 的 `_MAX_ROUTE_GEOMETRY_POINTS`）：单段路线最多 5 000 个几何点，全行程 40 000 个点。7 天 × 8 站、每段 150 点这类长路线是正常数据，不会被当成损坏；校验只读不写，不抽稀几何、不改站点和路线。
- 达到份数或体积上限时明确失败，不会自动淘汰旧记录，需要先删一份。单份超限只能重新规划更短的行程，删其他记录也放不下；当前行程仍可查看和导出 `.ics`。
- 恢复只读取本地副本，后端不可用时也能查看；恢复后回到第一天并清空选中站点。删除后有页面内「撤销删除」，撤销条保留到撤销、手动关闭或下一次删除。
- 每次读取都会重新校验。数据损坏、版本不符或体积异常时整份读取停止；存储里有无法识别的记录时只展示能确认的部分。这两种情况下保存、删除、撤销都会暂停，避免覆盖原始数据；确认不再需要后可在面板里二次确认清除，清除不可撤销。
- 清除浏览器站点数据会一并删除这些记录；无痕模式或禁用站点数据时保存不可用。

## 行程备份与导入（.json）

- 只有点「下载行程备份 (.json)」才生成文件并交给浏览器下载；渲染页面、预览文件、打开行程都不会触发下载，也不写 localStorage。文件是明文 JSON，可能包含你自己写的行程摘要、站点描述和地址，工具不做脱敏，分享前自行检查。
- 选文件后先解析并预览，只有点「保存到本地」才写入当前浏览器。导入与本地保存共用同一套结构校验（`savedTrips.checkTripShape`）：天数 1–31、每天站点 / 路段各不超过 100、全行程站点 / 路段各不超过 5 000、重复 `day` 与同一天里重复的站点 ID 直接拒绝、字段长度有上限、单段路线最多 5 000 个几何点、全行程最多 40 000 点。这些约束在预览前就生效，所以预览通过只说明结构和单份上限这两道检查过关；能否保存还取决于当时的总容量、份数余量与浏览器配额，超限时保存会明确失败。
- 单份 640 KB 的容量口径是真正写下的记录 `{ id, savedAt, trip }`（`savedTrips.savedTripRecordBytes`），包含 id 与保存时间的元数据，不只是 trip 本身；导出、导入、本地保存三处用同一个口径，卡在 640 KB 的边界文件不会出现「预览通过、保存必然失败」。超限一律 fail-closed：不生成文件、不写存储。
- 同 ID 覆盖必须在页面内二次确认，不弹 `confirm` / `alert`。确认时会重读存储，并同时比对 `savedAt` 和本地副本的完整内容快照，任一变化都拒绝写入并刷新快照让用户重新确认。localStorage 没有跨标签页的原子 compare-and-swap，「读 → 比对 → 写」之间其他标签页仍可能写入，这里只能缩小覆盖窗口，不保证绝对原子。
- 预览里的「行程来源」和「导出时间」都是文件自述：`source` 只代表文件自己标了示例 / 生成，证明不了行程的真实来源；`exportedAt` 不参与任何校验，展示时只接受规范 ISO 8601（统一换算成 UTC），其他内容一律显示「格式无法识别」，不把文件里的长文本原样渲染出来。
- 取消替换、确认失败、读取或写入异常时，本地已保存内容逐字节不变；数据损坏或含无法识别记录时按现有策略整体暂停写入，不静默丢弃或覆盖。
- 读取失败、写入失败、下载失败都只显示固定文案，不回显浏览器原始异常（可能带本机路径）。`File.size` 是 NaN / 负数 / Infinity 之类不可信值时保守拒绝，不读取文件内容。
- 内联确认的说明文字放在 `role="alert"` 里朗读，按钮放在紧邻的 `group` 中（不把交互控件塞进 alert）；确认框关闭后焦点回到「保存到本地」，放弃预览时回到文件选择框。

## 日历导出（.ics）

- 点「下载 .ics 文件」才生成文件并用浏览器下载到本机，需要你手动导入 iOS 日历 / Google Calendar / Outlook。不会上传，也不会修改或保存行程。
- 每个事件必须有合法日期和开始时刻。只有整份行程所有天的 `date` 都为空、且至少一天有站点时，面板才要求你先选「行程首日」；输入框默认空，必须由你主动选择。导出按天序号在真实日历上推算日期（跨月、跨年、闰年按实际日期算），仅用于本次导出，不写回原行程。存在任何真实日期时不会出现首日设置，缺日期的天只跳过。
- 时间是不带时区的 floating local time，导入端按导入设备的本地时区解释。换设备或跨时区时，事件对应的绝对时间会变（钟面时间不变），导入后请抽查第一场事件。
- 停留时长缺失、为 0、负数、非整数或超过 1440 分钟时，只写开始时间，不写结束时间，也不用默认时长补算。日历应用可能按自身默认时长显示一个结束时间，那不是行程数据的一部分。
- 坐标不写入 `.ics`，`LOCATION` 使用站点地址；地址或讲解为空就省略对应字段。
- 示例行程的事件标题带【示例】前缀，描述注明「示例行程数据，仅用于演示，未包含任何真实预约」。导出不写 STATUS、ORGANIZER、URL，不代表真实预订或已确认。
- 缺日期、日期非法、时刻非法或站点无名称的站点会被跳过并列出原因；没有有效事件时不会下载空文件。重复导出同一事件的 UID 保持不变。

## 本地编辑（内存草稿）

行程标题下方有「编辑这趟行程」入口。进入前先选「新增路段的出行方式」（步行 / 驾车）：本地编辑不会请求新路线，新增或重排站点后涉及的新路段只标记方式并标为「待重新获取」，不猜距离和耗时。

- 草稿只在内存里：改名称、地址、时间、停留、描述，增删、上移下移站点，都不会写 localStorage，也不请求后端。页面加载、应用、放弃都不会顺手保存。
- 改名称 / 地址会让该站坐标清空、相关路段变成「待重新获取」；只改时间 / 停留 / 描述时坐标与路线原样保留。原有数据的宽字段不会被二次校验或截断。
- 单站表单有独立输入缓冲：清空重输只在点「保存到草稿」时校验；有未提交输入时日期切换会暂停并给出说明，保存或取消后可跨日继续编辑同一份草稿。
- 编辑期间新规划、保存、恢复、备份导入导出与日历导出会明确暂停（表单被禁用并说明原因），健康探测照常可用。规划请求的等待在进入编辑时中止；停止等待不保证后端停止处理。
- 地图与列表实时显示草稿预览，页面会注明这是预览、尚未应用；原始行程和已保存记录保持原样。
- 「应用草稿」生成新的行程副本并替换当前视图：id 是新生成的，来源保持原值（示例衍生仍是示例），被改天的摘要换成诚实的本地编辑概要，旧提醒保留为「编辑前参考」。应用后需要保存仍要手动点「保存当前行程」；导出日历是新副本，不会更新之前导入的日历事件。
- 应用后有一次「撤销应用」可回到应用前的行程；撤销不删除已经显式保存过的副本。无实际改动的应用是空操作，不会新建副本。
- 浏览器存储不可用或后端离线时，编辑、预览与应用照常可用；导出 / 保存等需要存储或网络的功能各自提示。
- 地图空态措辞是中性的：全缺坐标时说「当前数据里没有可绘制的坐标：可能尚未定位，也可能定位没有成功」，不把本地新增站点或导入文件说成后端解析失败。

## AI 单日调整（独立预览）

行程下方的「AI 调整这一天」以当前选中的日期为目标。打开面板后日期切换、规划、保存 / 恢复 / 备份 / 日历导出都会暂停，关闭面板后恢复；健康探测不受影响。面板与本地草稿互斥：草稿未应用或放弃时按钮禁用，草稿里的输入不会被清掉。

- 打开面板不会发请求。填调整指令（1–500 字）、选这一次使用的出行方式（本日路段混合或为空时必须显式选），可选「同行人数」（1–50 的整数；留空就不发送人数，也不沿用规划表单里的值），点「生成调整候选」才调用一次 `POST /api/trips/days/replan`。
- 候选只出现在面板的对比区：左边是当前方案，右边是 AI 候选；地图和列表始终显示原行程。没点「应用候选」就不会改动当前行程，也不写 localStorage。
- 应用时父页面用最新行程与页面版本号重新核对候选：过期、容量超限、跨天站点 id 冲突等失败会在面板里说明，原行程保持不变。只有成功才替换目标日、生成新的行程副本 id 并递增页面版本号；其余天保持原对象与几何，来源不变（示例衍生仍是示例），已有保存记录不被改写。
- 应用后与本地编辑共用一次「撤销应用」；撤销不会删除已经显式保存的副本。应用本身不会自动保存，保存仍要手动点「保存当前行程」。
- 关闭面板、行程被外部替换或请求序号变化都会作废在途候选，迟到的响应不会覆盖页面。面板里的「停止等待」只停止本页等待，不保证后端或上游模型停止处理，也不保证停止计费。
- 有效的 AI 成功会说明规划服务可用；迟到的健康检查不能把这个结论翻成不可用。后端明确 `planner_ready=false` 时面板禁用生成，并说明本地编辑仍可用。
- 本轮该流程只用 mock 业务请求做前端测试，没有与真实模型服务联调；实际可用性取决于后端是否已部署该接口。

## 本日天气（独立查询）

当天行程下方有「查天气」入口。它是独立功能：不经过模型、不写 Trip、不写 localStorage，也不改地图和预算；后端明确 `planner_ready=false` 时照样可用。

- 打开面板不会发请求；点「查询天气」才调用一次 `GET /api/weather/day?lat&lon&date`，不做自动重试。查询进行中可以「停止等待」，只结束本页等待，不保证后端或上游停止处理。
- 坐标只取本日行程记录里带 WGS84 坐标的站点，可切换站点并明确本次按哪条记录的经纬度查；0 与负坐标是合法值。本日没有坐标就说明并禁用查询，不改用其它天、浏览器定位或按城市猜的坐标。
- 查询日期默认取当前天 `date` 字段；该字段缺失或不是合法日历日时留空，要求用户自己选，不拿今天冒充出行日。
- 站点选择、日期输入与查询按钮都是受控控件；改天、换站、改日期、行程对象或页面版本变化会立即清掉旧结果并中止在途请求；关闭面板、停止等待后迟到的响应也不会展示。
- 结果按后端信封展示：每日最高 / 最低温、降水概率、降水量、最大风速和天气类型。缺值、单位不符或范围异常显示「未知」；0 与负温按真值显示。WMO 代码只按官方表做确定性中文映射，表外代码保留代码并显示未知。
- `out_of_range` 只说明来源当前实际覆盖范围与该日暂无记录，不展示其它日期的天气；超时、502/503、网络失败与结构不符同样不会冒充上一次成功的结果。
- 面板区分「查询发起时间」与「本次获取时间」，不把 `fetched_at` 叫作预报更新时间；显示来源、目的地天气时区与采样网格点，并说明网格点不是站点精确位置。示例或导入文件的坐标只按记录查询，不宣称为已核验。
- 页面始终显示官方署名链接 [Weather data by Open-Meteo.com](https://open-meteo.com/) 与数据源说明链接；接口固定由后端请求 Open-Meteo，不迁移旧 MCP。
- 本轮只用 mock adapter / fetch 做离线测试，没有调用真实天气服务；实际可用性取决于后端是否已部署该接口。

## 停止等待

规划请求进行中可以点「停止等待」。本页会立即中止等待并忽略迟到的响应，可以马上改参数重新提交。这个动作只影响本页，不保证后端或上游模型停止处理，也不能保证停止计费。

规划失败、停止等待或仍在生成时，行程标题旁会显示一条归属说明：下方展示的是上一次的结果、本次没有生成新行程，或新行程正在生成中。这条说明只属于当前视图，不写进行程本身，保存、备份都不会带上它；规划成功、恢复本地副本或打开备份文件后即消失。

## 构建与测试

```bash
pnpm build           # tsc -b + vite build
pnpm test            # vitest 单测（含 App 集成测试）
pnpm preview         # 预览 dist 产物
```

`pnpm test` 也会跑 `dev-stub/server.test.mjs`：只起本机 http 服务核对桩的标识与 503 行为，不连外网、不依赖高德或模型。前端单测覆盖接口客户端、地图数据、瓦片状态、保存读写（`savedTrips.test.ts`）、日历生成（`calendar.test.ts`）与下载（`icsFile.test.ts`），以及保存、导出相关的组件测试。

接口地址：默认走同源 `/api`（dev 由 Vite 代理，生产需反代同源 `/api`），也可用 `VITE_API_BASE` 覆盖（如 `VITE_API_BASE=http://127.0.0.1:8001`）。注意 `VITE_API_BASE` 是构建/启动时读取的环境变量，不是运行时变量：开发在 `pnpm dev` 前设置，生产在 `pnpm build` 前设置；bundle 生成后再改系统环境变量不会重写已构建的产物。

## 契约要点（与后端约定）

- `GET /api/trips/example`、`POST /api/trips/plan` 返回同一 `Trip` 结构；`source: 'example'|'agent'` 决定「示例行程 / AI 规划」标识。开发桩只返回 `source: 'example'`，路段只含 `straight_line` / `unavailable`。
- 坐标一律 WGS84 `lng/lat`；前端转成 Leaflet 的 `lat,lng`。
- `route_type`：`navigation` 画地图服务路线、`straight_line` 画虚线并在图例标注「示意直线（非导航）」、`unavailable` 不画线只给文字。
- 健康检查会解析 `amap_configured`（只认布尔字面量，缺失/非法按未知处理）。它只说明「当前后端服务」是否配置了地图 Key，解释不了历史行程（导入/恢复）的坐标来源。
- `GET /api/weather/day?lat&lon&date` 直接返回天气信封（不套第二层），核心字段：`status`（`available` / `out_of_range` / `invalid_request` / `timeout` / `unavailable` / `failed`）、`requested_date`、`checked_at`、`fetched_at`、`coordinate{system,verified,requested,grid,grid_elevation_m}`、`source{provider,endpoint,docs_url,attribution_url,license}`、`coverage{first_date,last_date,count}`、`forecast{date,values,units,missing_fields}`。前端会核对 `requested_date` 与 `coordinate.requested` 是否匹配本次请求，不匹配按 `bad_payload` 处理。
- 天气六变量固定单位：`°C` / `mm` / `%` / `km/h` / `wmo code`；`values` 为 null 或单位不符时界面显示未知。`coordinate.verified` 固定 false，网格点不是站点精确坐标。
- 同一坐标的多个站点在地图上合成一个 marker，圆点显示站数，弹窗内逐站列出可访问入口；坐标按字面相等分组，不改动任何真实坐标或路线几何。
- 模型文案只按纯文本渲染，不做 HTML 注入。
- 后端不可达时：示例区给出明确错误与重试；规划区给出可操作的提示；地图缺瓦片/缺坐标各有空态。

### 仅刷新地图（地图刷新面板）

入口在行程区「本日天气」附近，只要求当前日已就绪；不要求 AI / planner 可用。

操作流程：

1. 点「仅刷新地图」打开面板，目标固定为当前日。
2. 在面板里显式选择「步行」或「驾车」，再点获取。
3. 获取完成后预览坐标与路段；确认无误后点应用。

限制与已知行为：

- 一次最多刷新 8 个站点；超过时面板会拒绝，不会截断成一次部分成功。
- 不调用 LLM，也不重新生成文字、时间或地址说明；地图耗时来自本次地图服务估算，不保证出行当天的实时交通。
- 地图未配置 Key 时接口返回 no_key，面板直接说明；当前行程仍可继续查看，模型不可用也不影响进入。
- 失败不会清掉当前行程的旧坐标和路线；开始新请求会作废上一份候选。部分解析成功的响应只做预览，应用前不会改动行程。
- 端点、邻接和出行方式未变时，本次只取得直线示意会保留旧导航并说明未重算；端点或方式改变时，不复用不匹配的旧导航。没有实际地图变化时无需应用，也不生成新副本。
- 取消（停止等待）只取消本页等待，不保证地图服务停止处理。
- 面板打开期间暂停规划、示例刷新、保存、恢复、导入导出、撤销和跨日切换；天气面板收起且不自动重查。
- 应用后仍是当前页面的新副本：不写 localStorage、不自动保存；需要留存请显式「保存当前行程」。
- 原来的 source（示例 / 导入文件）不会被升级成 AI 规划，导入文件的字节内容也不变。
- 应用可在页面内撤销一次；撤销同样会递增页面行程版本。

以上行为只由单元测试和纯函数测试覆盖，没有用真实高德 Key 或真实浏览器做过端到端验证。

## 每日站点上限偏好（本地编辑内）

本地编辑里可以设置「每天最多去几个站」的提示上限，用来在编辑行程时留意节奏。

- 默认关闭；开关打开后自行选上限值（1–8）和生效范围：all_days 检查所有天，changed_days 只检查这次编辑改过的天。
- 它只是当前编辑会话里的提示：不写入 Trip、不存 localStorage、不发给后端，离开页面就没了。下次编辑需要重新设置。
- 超过上限只做提示，不会自动删站或改行程，由你决定是否调整。
- 超过 8 站的旧行程照常能读能编辑，上限只约束提示开关里的取值。
- 这不是后端规划约束：AI 规划和单日调整不会按这个上限生成行程。
