# 可读路书 Markdown 导出

日期：2026-11-01。对应分支 `feat/interactive-travel-planner`，前置基线 `2494059`。

## 这是什么

行程备份与导入面板里新增一个「导出可读路书（Markdown）」子入口：把当前行程投影成一份便于阅读和分享的 `.md` 文本文件。它与 JSON 备份互补——JSON 备份用于恢复行程，Markdown 只用于阅读。

## 用户可见行为

- 子入口挂在「行程备份与导入」面板的文件工具区域，只在有当前行程时出现；没有行程时整个子入口不挂载，App 主界面无任何改动。
- **挂载不生成任何东西**：不生成文本、不建 Blob URL、不下载、不发请求、不写存储。只有点「预览路书（Markdown）」才生成一次文本。
- 预览是**只读纯文本**（`textarea readonly`），不渲染 HTML / Markdown；用户文本经过保守转义（Markdown 结构字符 + HTML 实体 + 控制字符），标题注入、代码块、链接、图片、表格与 `<script>` 都不会变成可执行结构或自动远程图片。
- 预览之后才出现「下载路书 (.md)」与「放弃预览」。下载只把**当前预览的同一份文本**交给浏览器——下载函数不接收生成入口，不存在下载时悄悄重新生成另一份内容的可能。
- **渲染期作废守卫**：预览绑定行程 id + 完整内容快照（序列化），不只比对象引用。换行程、同 id 内容变化（撤销、编辑、导入打开）后，旧预览与下载在渲染期立即作废并在提交后永久清除——即使回到与首次相同的内容（same-id 修改再撤销、不同 Trip 来回），旧预览也不复活，须重新预览。生成失败（此时没有预览）留下的错误通告同样随行程上下文变化清除：换行程或同 id 修正内容后，旧错误不挂到新行程上，也不自动重新生成。行程无法序列化（如被塞入 BigInt 等字段）时生成直接 fail closed，不给出无法守护的预览。生成侧的 `bad_limit`（输出上限配置非法）在界面上显示「这是程序配置问题，与行程内容无关」的固定文案，不用行程非法的文案指责用户数据。
- 放弃预览后焦点回到「预览路书（Markdown）」按钮，不抢其它控件焦点。
- 下载失败保留合法预览可直接重试；错误文案固定，不回显原始异常或路径；成功只称「已发起浏览器下载」，不保证文件已落盘。Blob 构造、anchor 属性设置、插入、延迟回收调度各自的异常都在管控内：未发起下载的失败会回收已创建的 URL 并移除已插入的节点；已发起下载后调度失败会改用默认延迟调度兜底回收，连默认调度也失败才按 best-effort 交由页面关闭回收；回收幂等，调度器先执行回调再抛错也不会重复回收。不做无条件同步回收——那会取消 Firefox 已开始的下载。

## 导出内容契约

只投影 `frontend/src/lib/api.ts` 里 Trip v1 的已知字段：

| 内容 | 语义 |
| --- | --- |
| 标题 / 目的地 / 摘要 / 天数 | 原记录值；空值写「未提供」 |
| 行程来源 | `example` / `agent` 按记录自述展示，明确标注「记录自述」，不冒充真实模型来源 |
| warnings | 原样进入「记录内提示」小节 |
| 每天 | 日期缺失写「日期未提供」，不改成推断日期；站点按记录顺序展示时间 / 停留 / 地址 / 描述 / 坐标 |
| 路段 | 按原 `from_stop_id` / `to_stop_id` 匹配站点名；匹配不到如实标注，不猜名字 |
| route_type | `navigation` / `straight_line` / `unavailable` 明确区分：直线不说导航，未知不说可达；导航路线标注「按记录原样导出，本次未重新计算路线」 |
| 距离 / 耗时 / 停留 | `null` 写「未提供」；**0 是合法记录值照写**，不误作缺失、不猜值填 0 |
| 坐标 | 有坐标纯文本展示（WGS84）；无坐标写「未提供」，不补位置 |
| geometry | 不输出：几千个点对阅读无价值 |

边界：

- 导出按原记录整理：用户摘要 / 描述里自己写的营业、票价、预约、天气等说法原样保留，不删除也不核实；导出本身不新增任何此类信息，固定说明写明「没有因导出而核实」。独立 POI / 天气信封不进入导出。
- 未知 extra 字段（包括凭据状对象）一律不输出。
- 用户自己的描述**不做自动脱敏**；界面提示「分享前请检查一次」，不堆实现免责声明。
- 用户文本转义是**无损**的：反斜杠一并转义（含反斜杠的控制串不会重新变成 Markdown 结构）；控制字符（含 Tab）转成可见的 `U+XXXX` 记号，不静默删除；换行转成行尾两空格的硬换行。多行 / 标题 / 反引号 / 图片 / HTML / 表格都不会变成活跃结构。
- 不写导出时间、不读时钟：同一 Trip 输出逐字节相同（确定性）。
- 文件开头固定一行说明：这是当前记录的阅读版导出，营业时间、票务与路线实时状态没有因导出而核实；恢复行程请用 JSON 备份。

## 校验与门禁

复用与本地保存同一套约束：

1. `isTripLike` 契约校验 + `checkTripShape`（重复 day / 站点 ID、字段长度、数量、每段 5000 点、全行程 40 000 点预算）——与 `tripTransfer.ts` 同源；
2. 生成后按 UTF-8 实际字节做 **1 MiB 输出门禁**（`MAX_TRIP_MARKDOWN_BYTES`）：调用方传入的自定义 `maxBytes` 只能收紧上限（正数且不超过 1 MiB），非法配置（NaN / Infinity / 负数 / 超过上限）返回独立的 `bad_limit` 固定文案，不伪装成行程非法；超限 fail-closed 返回固定文案，不截断、不回显内容。

失败不产出半份文件；行程本身不受影响。

## 文件名与下载

- 文件名复用 `tripFile.ts` 的 `safeTripBackupFilename` 安全 base，固定换 `.md` 后缀：清洗非法字符、80 码点限长、Windows 保留名保护、同一行程文件名稳定。
- MIME 固定 `text/markdown;charset=utf-8`。
- 下载走与 `tripFile.ts` / `icsFile.ts` 相同的 DOM 模式：显式调用才创建 Blob URL，成功延迟 1 秒回收（Firefox 兼容），失败（点击抛错）立即回收；Blob 构造、anchor 属性设置、插入失败都会回收已创建的 URL 并清理已插入的节点；`revoke` / `anchor.remove` / 调度自身的异常单独吞掉，不冒充业务结果。测试可注入 `document` / `createObjectURL` / `revokeObjectURL` / `schedule`。
